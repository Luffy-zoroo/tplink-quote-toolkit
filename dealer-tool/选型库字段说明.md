# 选型库字段说明

选型库是一份本地 JSON（默认 `<数据目录>/tplink_dealer_backup.json`，路径由配置项
`dealer_backup_json` 指定），存的是「平台能卖的型号 + 官网规格 + CRM 在产与价格 +
拼好的参数」，用来在不登录任何系统的前提下做选型检索。

**它不替代任何系统。** 平台说能卖、CRM 说在产、官网说有这个规格，三件事分别来自三个源，
本文说明每个字段来自哪、能不能直接拿去配单。

---

## 一、先记住三条红线

| 红线 | 为什么 |
|---|---|
| **价格不是配单口径** | 库里价格是 CRM 价格手册的**快照**。配单必须实时查 CRM，折扣口径每次现问。库里只用来粗判「这机器贵不贵」 |
| **备用参数不是配单首选** | `param_backup` 里官网自动拼的那份**未经人工提炼**，且**一条加分项都没有**（官网不知道哪条该标★）。控标库有这个型号时，一律用控标库那份 |
| **停产只认 CRM** | 平台那个 `haltProduct` 字段实测**基本不更新**：2850 个型号里 0 条标停产，而 CRM 同期判了 185 个停产。拿平台字段判停产会直接把停产的机器配进清单 |

## 二、字段表

### 2.1 平台侧（合作伙伴平台）

| 字段 | 含义 | 备注 |
|---|---|---|
| `model` | 型号 | 主键 |
| `name` | 平台产品名 | 常带「套装」「XX版」等后缀 |
| `productId` | 平台产品 ID | 抓详情用 |
| `officialRelateId` | 官网产品 ID | **空 = 平台没给**，多为平台专供/套装/配件。可用 `official_index.py match` 从官网反查补上 |
| `id_from` | 官网 ID 哪来的 | `official_index` = 反查补的（平台原本没给），其余为空 = 平台自带 |
| `brand` | 品牌值 | `TP` / `MERCURY` / `水星` 等 |
| `cat1` / `cat2` | 一级 / 二级品类 | ⚠️ 平台类目会自己漂移（同型号换过类目），**认形态以型号和产品名为准**，`cat2` 只作粗筛 |
| `industry` | 行业产品 / 渠道产品 | |
| `price_untrusted` | 平台价格 | **不可信，已弃用**，仅供对照。真实价格看 `crm` |
| `detail_raw` | 平台详情全部非空字段 | 含 `haltProduct`（不可用）、`bargainClearance`、`boxNumber`、`ecommerceVersion` 等 |
| `siblings` | 同系列其他型号 | 选型时「这系列还有哪几款」直接可查 |
| `halt_platform` | 平台的 `haltProduct` | **恒为 False，不可用**，只留作观察。`refresh` / `fill` 只写这个字段 |
| `halt` | 停产标记（权威） | **独占字段：只由 `enrich.py crm` 按 CRM `lifeCycle` 写入**，其他脚本不许碰；`halt_from` 记来源。`enrich.py stats` 会自查 `halt` 与 CRM 是否一致，不一致直接报警 |

### 2.2 官网侧（tp-link 官网公开接口）

| 字段 | 含义 |
|---|---|
| `spec` | 规格参数，三级结构：`[{group, name, values[]}]`，`group` 是大分组（如「图像与视频参数」「常规参数」） |
| `desc` / `spotlight` | 产品描述 / 卖点 |
| `desc_from` | `platform` = 描述来自平台；`official` = 来自官网 |
| `official_url` | 官网页地址，形如 `product_<id>.html` |

官网 id 是**连续自增**的（`publicservice/productinfo?brand=TPLINK&productModel=<id>`，
参数名虽叫 `productModel`，实际传 id）。`official_index.py build` 就是把
1~4700（+ 水星/迅捷各 900）遍历一遍，建「型号 → 官网页」反查表，
用来补平台没给 id 的那批。**索引文件 `tplink_official_index.json` 约 940 KB，和选型库同目录，不进 Git。**

### 2.3 CRM 侧（`rec['crm']`，价格手册快照）

| 字段 | 含义 | 备注 |
|---|---|---|
| `lifecycle` | `PRODUCTION` / `HALT_WARNING` / `HALT` | **权威口径** |
| `lifecycle_cn` | 在产(量产) / 停产预警(在产中) / 停产 | |
| `catalog_price` | 面价（标准目录价） | **通常**最高，但实测约 21% 的型号批发价高于面价，别当铁律 |
| `wholesale_price` | 批发价 | |
| `price` | 现价（价格手册里的 `price`） | 配单看这个；实测 ≈ 面价 × `catalog_ratio`，但高低顺序不恒定，别用面价乘系数去反推 |
| `catalog_ratio` / `wholesale_ratio` | 面价 / 批发价的折扣率 | 原样存 CRM 值 |
| `business_discount` | 业务折扣 | ⚠️ **独立字段，不是「现价÷面价」**。值域 0.1~1，只有部分型号有值。实测它与现价/面价之比不一致（中位差 0.05），**不能拿它反算现价**；真实口径需向商务确认，故原样存值、不替它编语义 |
| `line_info` | 阶梯价原文，如 `0~9999999:￥2300` | |
| `labels` / `label_cn` | 产品标签（多值） | `PROJECT_PRODUCT`=项目机型、`CUSTOMER_CUSTOM`=客户定制、`CAN_CUSTOM`=可定制、`DEMAND_PRODUCTION`=按需生产、`BARGAIN_CLEARANCE`=特价清仓、`VALUE_ADD`=增值产品、`ECOMMERCE_VERSION`=电商版 |
| `is_project_model` | 是否项目机型 | `labels` 含 `PROJECT_PRODUCT` **或** `seriesValue` 含「项目机型」。用 label 判比只看 seriesValue 更全 |
| `is_custom` / `is_bargain` | 客户定制 / 特价清仓 | |
| `series` / `tax_name` | CRM 产品系列 / 税务品名 | |
| `order_types` | 适用订单类型 | |
| `unit` / `box_number` | 单位 / 装箱数 | |
| `line_valid` / `product_valid` | 该价格行有效 / 产品有效 | 取代表值时优先 `line_valid=True` |
| `variants` | 同型号的价格行条数 | CRM 里同型号可能多行（不同区域/OU），这里取了代表值 |
| `fetched_at` | 取数时间 | |

### 2.4 派生（`rec['param_backup']`）

| 字段 | 含义 |
|---|---|
| `items` | `[{text: '1、...', is_bonus: bool}]`，和控标库同格式 |
| `count` | 条数 |
| `source` | `kongbiao` = 控标库有；`official_spec` = 官网规格自动拼；`null` = 都没有 |
| `from_kongbiao` | 是否来自控标库 |
| `note` | 口径说明（自带「非配单首选」字样） |

**控标库已有的型号，这里只记条数、不存参数副本** —— 同一段文字存两处，控标库一改这边就不动了，
等于制造两份互相打架的口径。要用请直接查控标库。

## 三、更新流程

```bash
cd dealer-tool

python backup.py refresh                  # 平台列表 + 新品详情（需合作伙伴平台账号）
python backup.py --workers 10 --fast --force fill   # 官网规格/描述全量重抓（只打官网，约 5 分钟）
python backup.py tidy                     # 描述里残留的 HTML 压成可读文本（幂等，跑几次都行）
python official_index.py build            # 官网产品索引：遍历 id 建「型号→官网页」反查表（约 8 分钟）
python official_index.py match            # 平台没给官网 id 的型号，回填 id 并补规格
python enrich.py crm                      # CRM 全量价格手册 → 在产状态 + 三档价 + 折扣
python enrich.py params                   # 生成备用控标参数
python enrich.py stats                    # 终端看覆盖度
python report.py                          # 生成 Markdown 报告（含停产清单）
python backup.py html                     # 生成离线查看器 HTML
```

`enrich.py crm` 是**一次拉全量**（8397 条价格手册约 12 秒），不是逐个型号查——
`productModel` 传空串就是不过滤，接口支持。

`--force` 全量重抓时，**抓空的字段不会覆盖已有值**（`store.upsert` 里对空值做了保护），
所以官网偶尔抽风不会把好数据洗掉。

### 验证

```bash
python enrich.py --selftest          # 27 项
python report.py --selftest          # 9 项
python official_index.py --selftest  # 12 项
python pick.py 双光全彩 半球 --limit 5 --no-gate   # 看状态/价格/参数是否都出来
```

## 四、踩过的坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 平台 `haltProduct` 不可用 | 2850 个型号 0 条标停产，CRM 同期判 185 个 | 停产只能看 `crm.lifecycle` |
| 跳过分组的匹配用 `in` | 官网分组叫「**图像与视频参数**」，用 `'视频' in group` 把摄像机核心参数整段丢掉（某型号 11 条规格只剩 4 条） | 改成 `startswith` |
| 只看 `seriesValue` 判项目机 | 有型号 `productLabel` 标了 `PROJECT_PRODUCT` 但 `seriesValue` 没标 | 以 `productLabel` 为主 |
| `businessDiscount` 当折扣率用 | 拿它乘面价算出来的价对不上现价 | 它和现价折扣率是两个概念，别相乘 |
| 假设「面价 ≥ 批发价 ≥ 现价」 | 实测只有 77.6% 符合；20.9% 是批发价高于面价，39 条现价略高于面价 | 三档原样存，不做换算；配单只看 `price` |
| 按「摄像」过滤查品类 | 会漏掉 F系/G系/筒机/半球等类目 | 用具体 `cat2` 或型号正则 |
| `--fast fill` 把描述洗成 HTML | 平台描述是纯文本，官网 `spotlight` 是 `<ul><li>` 原文；全量重抓后 2255 条描述变成 `<ul><li>…` | `store.plain_desc()` 在入库侧清洗，已有数据用 `backup.py tidy` 洗一遍 |
| 清洗时用正则压「空格+斜杠」 | 会把 `1/2.8英寸`、`DC/PoE`、`VSWR:<1.25` 改成 `1 / 2.8英寸`，参数直接变错 | 分隔符走 `\x00` 占位符，只把占位符换成 ` / `；真实的 `<` 后跟数字时保留 |
| 清洗后变空就写回 | 原文只有 `<p></p>` 这类的，清洗完是空字符串，写回等于删描述（丢过 23 条） | `clean` 为空时不写回 |
| 用平台接口按型号查官网页 | `findProductPageByModel` 对本账号报 `-1002 无权限`，535 个型号抓不到规格 | `official_index.py` 遍历官网公开接口的连续 id（1~4700），建反查表绕过权限 |
| 遍历官网 id 时多线程写索引 | 多线程同时改 `items` 又在序列化，直接 `RuntimeError: dictionary changed size during iteration`，跑一半崩掉 | 入库 + 落盘都放进 `threading.Lock` |
| 水星/迅捷的规格字段不一样 | 只读 `specification`（HTML 表格）导致 `groups=0`，744 个水星产品全部「无规格」 | 优先读 `specification2`（JSON 结构），再回退 `specification` |
| 型号名带销售包装后缀 | `MS05CP 件装`、`（4只装）` 这类在官网是同一个型号，精确匹配全落空 | `_SUFFIX` 剥掉「件装/套装/(N只装)」再匹配 |
| 官网 id 空间混着作废条目 | 有 `TL-IPCTest`、`TL-SP1030H_作废`、`test_作废` 这类，会被误当成新品 | `_is_junk()` 过滤「作废/Test/测试/删除/临时/废弃」 |
| 给缺 id 的型号补记录时 | `make_record` 里 `industry` 是 `bool(...)`，传空详情会被算成 `False`，把行业标记刷掉 | 补记录时把原记录的 `projectProduct` 带上 |
| 平台抓取覆盖了 CRM 的停产判定 | `fill` / `refresh` 会把平台 `haltProduct`（恒 False）写进 `halt`，**30 个 CRM 判停产的型号被刷回「在产」**，页面照常显示在产 | 平台侧字段改名 `halt_platform`；`halt` 由 `enrich.py crm` 独占写入；`stats` 加一致性自查 |

## 五、体积与分发

- 完整库约 23 MB（2850 个型号，含官网规格全文 + CRM 价格块 + 备用参数）
- 官网产品索引约 940 KB（5271 个官网产品，型号→官网页反查表）
- 离线查看器 HTML 约 19 MB（数据内嵌，单文件可离线打开，支持 `#型号` 直接定位）
- **两者都不进 Git**（`.gitignore` 里由 `tplink_*.json`、`*.xlsx` 兜底），走内部共享盘分发
