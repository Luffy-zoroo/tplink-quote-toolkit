# 报价清单自动填充助手（tplink-quote-autofill）

> 一句话说明：**丢一个工程清单 Excel 进来，自动把「控标参数」和「价格」填好**——参数优先查本地控标库，查不到就去 TP-LINK 官网抓产品特性，价格自动算好折扣并取整，最后把带品牌字眼的词全部洗掉。

---

## 一、这个技能能干什么

| 能力 | 说明 |
|---|---|
| 📋 **自动填控标参数** | 按清单里的型号，先去本地控标库 `tplink_kongbiao_data.json`（658 个产品 / 7800+ 条参数，含 543 条 ★▲ 加分项）找；找不到就自动去 TP-LINK 官网抓「产品特性」文字填进去 |
| 💰 **自动算价格** | 登录 TP-LINK 销售 CRM 拉标准价 + 业务折扣，按规则算成你要的折扣价，无折扣的直接给面价 |
| 🔢 **价格自动取整** | 有折扣算出来的价格，自动向上取整到个位是 **0 / 2 / 5** 的整数，不留小数 |
| 🧩 **组合型号自动加总** | 型号写成 `TL-VS7500+TL-NVDU7606S*4` 这种一整套配置的，**参数填主型号、价格把配件全部加起来** |
| 🧼 **品牌词洗白** | 参数里出现的「商用云平台、商云APP、TUMS、算法商城、TP-SRC」这类品牌指向性字眼，**自动替换成中性说法**，避免投标被认定排他性条款 |
| 🛡️ **不动你填过的内容** | 只填空单元格。你已经填了的型号、参数、价格，一个都不改 |
| 📊 **出一份核对报告** | 跑完生成 JSON 日志 + HTML 对照页，哪条来自控标库、哪条来自官网、哪条没查到，一目了然 |

## 二、怎么用它（给同事看的）

### 装法（两种，任选一种）

**推荐：在仓库根目录跑一键脚本**（会把 5 个技能一起装好并生成初始配置）

```bash

cd tplink-quote-toolkit
pip install openpyxl
python install.py
```

**或者手动**：把整个 `tplink-quote-autofill` 文件夹，放进你电脑的：

```
C:\Users\<你的用户名>\.workbuddy\skills\

放好后目录长这样：

```

    ├── README.md             ← 就是本文件
    ├── scripts\
    │     ├── autofill_quote.py    ← 主程序

    │     ├── nat_classify.py      ← 全清单设备枚举 + NAT 分类
    │     ├── capacity_check.py    ← 带机量核算
    │     └── tpkit_config.py      ← 配置读取（路径都由它决定）
    └── references\
          ├── kongbiao_library.md   ← 控标库字段结构说明

放完**重启 WorkBuddy**，然后在对话里直接说需求就行，比如：

> "把这个清单的控标参数和价格填一下"（然后把 Excel 拖进来）

### 装完技能，还要装「数据包」（重要）

技能本身**不含数据**。控标库 / 选型库 / 价格备份 / License 映射 / 防火墙规格这五个 JSON
是内部数据，单独打成一个 **`TP-LINK清单工作流-数据包-<日期>.zip`** 放在**内部共享盘**（公开仓库里故意没有）。

```bash
# ① 把数据包解压到任意位置（不用放进技能目录），比如 D:\TP-LINK工作流数据\
# ② 在该目录下跑一次，自动把配置里的数据路径指向本包（旧配置自动备份）
cd D:\TP-LINK工作流数据
python 生成配置.py            # 加 --dry-run 可先看会改什么
```

换电脑 / 挪了目录 → **重跑一次 `生成配置.py`** 就行，不用手改路径。
包内 `00-先读我.md` 有更完整的三步安装和 FAQ。

包内文件名换了，但**程序看的是配置里的路径、不看名字**，只要对得上就没问题：

| 包内文件 | 程序原名 | 少了会怎样 |
|---|---|---|
| `数据/1-控标参数库.json` | `tplink_kongbiao_data.json` | 参数全走官网抓，**拿不到 ★ 加分项** |
| `数据/2-选型库.json` | `tplink_dealer_backup.json` | **选型做不了**（候选型号全靠它反查） |
| `数据/3-价格备份.json` | `tplink_crm_price_backup.json` | 只能联网查价，CRM 不通就没价 |
| `数据/4-License映射.json` | `tplink_license_map.json` | 防火墙多合一库的 SKU 取不到 |
| `数据/5-防火墙规格.json` | `tplink_fw_spec_20251120.json` | 防火墙带机量/吞吐无本地兜底 |

> ⚠️ 数据包别外传、别上传到任何公开位置。

### 还要准备的账号

**TP-LINK 销售 CRM 账号**（要算折扣价就必须要）

需要能登录 `$CRM_BASE/crm` 的账号密码（内网域名，得在公司网络或本机代理下）。
脚本会自动从你的 WorkBuddy 记忆文件里读账号密码；读不到就问你要，或者用 `--email` / `--password` 传。

> 只要面价（不要折扣）的话，加 `--no-crm` 就不需要账号了。

## 三、价格是怎么算的（重要，务必看）

### 1. 折扣换算方法（长期有效）

CRM 里每个型号带一个**业务折扣率**（`businessDiscount`）。由它可换算出另外两档：

| 业务折扣率 | 片区折扣率 | 总部折扣率 |
|---|---|---|
| 0.45 | 0.43 | 0.40 |
| 0.43 | 0.40 | 0.40 |
| 0.39 | 0.34 | 0.32 |
| 0.32 | 0.27 | 0.25 |

**折扣价 = 标准价 × 折扣率**

**哪类产品用哪档**：监控类（摄像机 IPC、NVR、存储、解码器…）走**片区**；
其他类（交换机、AP、AC、门禁、布线…）走**总部**。
型号前缀速查——`TL-IPC/TL-NIPC/TL-AIPC/TL-NAIPC/TL-NVR/TL-NVS/TL-NVD/TL-NVDU/TL-VS/TL-SDC/TL-TUMS` 走片区；
`TL-KBG/TL-EC/TL-EML/TL-EBL/TL-AH/TL-AS/TL-CR/TL-CW/TL-DEB/TL-CARD/TL-VE` 走总部。

> ⚠️ 两个易搞反的：**拼接屏 `TL-VE`** 和 **网络控制键盘 `TL-NK2000`** 都走**总部**。

**只有 `seriesValue == '项目机型'` 的型号有业务折扣**，其余系列（域联产品/双频AP/其他附件）
直接取标准价。

### 2. 这一单给几折 —— 每次问你，脚本不预设

上面是**换算方法**（怎么算）。**具体某一单给片区还是总部、给几个点，是商务决策**，
每次由你指定，通过 `--rate-spec` 传给脚本：

| 想怎么算 | `--rate-spec` 写法 |
|---|---|
| 全部取标准价（不打折） | `{"mode":"none"}` |
| 全部都按同一个折扣率 | `{"mode":"flat","rate":0.34}` |
| 项目机型统一走片区 0.34 | `{"mode":"by_field","field":"seriesValue","values":["项目机型"],"rate":0.34}` |
| 项目机型按类别自动分片区/总部 | `{"mode":"by_class","field":"seriesValue","values":["项目机型"],"biz_to_pq":{"0.32":0.27,"0.39":0.34},"biz_to_hq":{"0.32":0.25,"0.39":0.32}}` |
| 按你当次给的对照表折算 | `{"mode":"by_discount_table","field":"seriesValue","values":["项目机型"],"table":{"0.32":0.27,"0.39":0.34}}` |
| **两档分开：项目机一个口径、渠道机另一个** | `{"mode":"by_field","field":"seriesValue","values":["项目机型"],"rate":0.36,"else_rate":0.95,"hit":{"base":"price"},"else":{"base":"catalog"}}` |
| **跟着型号走：各自业务折扣率 −2 点** | `{"mode":"from_business","offset":-0.02,"base":"price"}` |
| 两档里一档跟着型号走 | `{"mode":"by_field","field":"seriesValue","values":["项目机型"],"rate":{"from":"business","offset":-0.02},"else_rate":null}` |
| 查片区表换成片区折扣率，再 −2 点 | `{"mode":"by_class","field":"seriesValue","values":["项目机型"],"class":"pq","offset":-0.02}` |

- **不传 `--rate-spec`** → 脚本不猜，打印提示后先按「全部取标准价」跑，提醒你带参数重跑。
- 同一份清单：`by_class` 口径下行12=1616（走总部），`by_field 0.34` 口径下=1717（走片区）。
  口径不同结果不同，脚本不替你决定。

**`rate` 可以写表达式**（折扣率不能写死的时候）：

| 表达式 | 等于 |
|---|---|
| `0.34` | 固定折扣率（等价老写法） |
| `{"from":"business","offset":-0.02}` | 该型号业务折扣率 − 2 个点 |
| `{"from":"pq","offset":-0.02}` | 查片区表换成片区折扣率，再 − 2 个点 |
| `{"from":"hq","offset":-0.02}` | 查总部表换成总部折扣率，再 − 2 个点 |
| `{"from":"auto","offset":-0.02}` | 监控类走片区表、其余走总部表，再 − 2 个点 |

- **什么时候必须用表达式**：项目机型的业务折扣率每个型号不一样，写死 `0.34` 会整片算错
- 算出来折扣率 ≤ 0 或 > 3 → 该行**价格留空**并说明（`PricingError`），不按面价凑数
- 没有 `businessDiscount` 的行遇到 `from: business` → 基准价原样，不猜折扣

**两档口径（项目机 / 渠道机）怎么用**：渠道机和项目机不是一套定价逻辑，
清单里两种货混着时必须分开设，别拿一个口径套全表。

- `rate` = 命中档（项目机型）的折扣率，`else_rate` = 另一档（渠道机）的折扣率
- 任一写 `null` = 该档不打折，**基准价原样不取整**
- `hit` / `else` 里的 `base` 选基准价：`price`（标准价，默认）/ `catalog`（目录价）/ `wholesale`（批发价）
- 两档完全一样时可以退回 `{"mode":"flat","rate":…,"base":…}`，不依赖 `seriesValue`
- ⚠️ `seriesValue` 要查 CRM 才有，所以 `--no-crm`（只填参数）时两档口径都不生效

### 3. CRM 里取哪些数（这部分是稳定的）

登录 `$CRM_BASE/crm`（内网域名，得在公司网络或本机代理下），
调 `GET /api/line/findByPage?productModel=<型号>` 取：

| 字段 | 含义 |
|---|---|
| `price` | **标准价（面价）** |
| `businessDiscount` | 业务折扣率（可能为空） |
| `seriesValue` | 系列值，如 `项目机型` / `域联产品` / `双频AP` / `其他附件` |

> `productModel` 是**模糊匹配**，返回结果里会混入别的型号，要按精确型号再筛一遍。
> 同一型号命中多条（不同 OU/区域/版本）时**全部列出交你裁决**，不要自己挑。
> 详细接口说明见 `references/crm_access.md`。

### 4. 取整规则

| 情况 | 怎么处理 | 例子 |
|---|---|---|
| 算出来是小数 | 向上取整到个位是 **0/2/5** | 212.85 → **215**；331.10 → **332** |
| 算出来正好是整数 | **保持原样，不动** | 3900×0.34 = 1326 → 保持 **1326** |
| 无折扣，取面价 | 原样保留（面价本身多是整数） | 137.5 → 保持 **137.5** |
| 你自己手动加点产生小数 | 同样向上取整到 0/2/5 | — |

### 4. 不对外暴露折扣

报价文件里**不写**「业务折扣 / 折扣率 / 标准价」这些字眼，价格列标题用中性的「含税单价(元)」，也**不加备注列**说明这是折扣价。参数该填照填。

### 5. 组合型号（一整套配置）怎么算

型号列里写了好几个型号的，是「一整套」的意思，**不是单价只算一个**：

| 型号列写法 | 意思 | 参数填谁 | 单价怎么算 |
|---|---|---|---|
| `TL-VS7500+TL-NVDU7606S*4` | 1 台解码矩阵 + 4 块板卡 | TL-VS7500 | 9720 + 2484×4 = **19656** |
| `TL-EML100+TL-EML100-LZ` | 1 把锁 + 1 个支架 | TL-EML100 | 100 + 50 = **150** |
| `TL-EBL100+TL-EBL100-U` | 1 个电插锁 + 1 个下门夹 | TL-EBL100 | 80 + 25 = **105** |
| `TL-FC311A-3/TL-FC311B-3` | 收发器 A/B 一对 | TL-FC311A-3 | 74 + 74 = **148** |
| `TL-EC100-M18*2` | 一个型号买 2 个 | TL-EC100-M18 | 702×2 = **1404** |

三个要点：

1. **参数只填第一个（主）型号**的参数，后面的配件不参与参数。
2. **价格把所有配件加起来**。每个配件**各自按当次指定的口径**算（可能一个打折、一个不打），
   再乘自己的数量，最后相加。
3. **`*N` 只作用于紧挨着的那个型号**：`A+B*4` 是 A×1 + B×4，**不是** (A+B)×4。

一句话记：**参数认第一个，价格全加总；折扣口径每次问。**

> ⚠️ 型号名里带 `/` 不一定是"两个型号"。如 `TL-AP1206GC-PoE/DC易展版` 的 `/DC`
> 是电源规格后缀，要当成**一个**型号（且原样带斜杠去查 CRM）。脚本已处理。

想自己验证脚本的组合逻辑没被改坏，跑这个（不联网，秒出结果）：

```bash
python scripts/autofill_quote.py --selftest
```

## 四、参数里的品牌词怎么处理

投标时参数里出现自家品牌名或专有平台名，容易被认定为排他性条款。脚本会自动把这些词换成中性说法：

| 原词 | 替换为 |
|---|---|
| TP-LINK商用网络云平台 | 商用网络云平台 |
| 商云APP | 商用网络管理APP |
| 商云 | 商用网络管理平台 |
| TUMS综合管理平台 / TUMS | 综合管理平台 |
| TP-SRC码控算法 | 智能码控算法 |
| 算法商城 | 算法应用商店 |
| TP-LINK商用 / TP-LINK | 商用 / （删除） |
| 海康 / 大华 / 宇视 | 主流品牌 |

**单独跑清洗**（不填表，只洗一段文字）：

```bash
python scripts/sanitize_params.py "参数文本内容"
```

想检查一段文字里还有没有漏网的品牌词，脚本里的 `scan_text()` 会返回命中位置。

如果某次不想清洗，加 `--no-sanitize` 参数跳过。

## 五、命令行怎么调（进阶）

一般直接在对话里说需求就够了，不用手敲命令。真要手动跑：

```bash
python scripts/autofill_quote.py --xlsx "D:\路径\你的清单.xlsx"
```

常用参数：

| 参数 | 作用 |
|---|---|
| `--xlsx <路径>` | 清单文件路径（必填） |
| `--sheet <名称>` | 工作表名，不填用第一个 |
| `--header-row <n>` | 表头在第几行（默认 2） |
| `--model-col <列>` | 型号所在列，如 `I` |
| `--param-col <列>` | 参数要写进哪列，如 `J` |
| `--price-col <列>` | 价格要写进哪列，如 `K` |
| `--kb <路径>` | 控标库 JSON 路径 |
| `--email` / `--password` | CRM 账号（不填自动从记忆读） |
| `--rate-spec <JSON>` | **本次折扣口径**（见第三节）。不传则先按"全部取标准价"跑并提示 |
| `--no-crm` | 不查 CRM，只要面价/不填价 |
| `--no-sanitize` | 不做品牌词清洗 |
| `--out <路径>` | 输出文件路径（默认原地改，自动留 `.bak` 备份） |
| `--report <路径>` | 核对报告输出路径 |

**运行前会先备份原文件**（`.bak_before_fill`），改错了可以回滚。

## 七、已知边界（别踩）

- **官网抓取偶尔失败**：官网改版时 `#smbproductFeature` 选择器可能失效，脚本会回退到规格表；再不行就标记「没查到」，需要手工补。
- **CRM 型号是模糊匹配**：`productModel` 参数是模糊匹配，脚本会在客户端再按精确型号筛一遍；同一型号多条价格（不同 OU/区域）会都列出来，需要你确认用哪条。
- **你手填的价格脚本不会改**：这是硬约束。如果脚本算出来和你填的不一样，说明你当时有特殊商业决策（加点了 / 谈判价 / 按对卖），脚本会**保留你的值**并在报告里标出来。
- **组合型号容易算漏**：`A+B*4` 这种必须把配件全加起来。别只看第一个型号的价——这是最容易犯的错。
- **CRM 是内网域名**：不在公司网络或没开代理时登录不上，价格就取不到，脚本会跳过并提示。
- **控标库需要定期更新**：新产品上市后控标库没有，就会全走官网。

## 八、常见问题

**Q：我只要参数，不要价格，行不行？**
A：行。加 `--no-crm`，价格列就不动。

**Q：我已经填了一半，会被覆盖吗？**
A：不会。脚本只写空单元格，已有内容的单元格一律跳过。

**Q：参数填进去格式很乱怎么办？**
A：控标库里的参数本身是分条的，填进去是多行文本；如果清单要求的是一整段，可以在 Excel 里把单元格的「自动换行」关掉。

**Q：型号清单里有非 TP-LINK 的产品？**
A：会被标记「没查到」，不会乱填。需要你手工处理。

**Q：控标库在哪更新？**
A：就是数据包里的 `数据/1-控标参数库.json`。拿到新版本直接**覆盖同名文件**即可，配置不用动。
它是 JSON 数组，按 `{category, product_name, model, params_raw, param_items}` 结构往里加也行。

**Q：型号列里写成「TL-VS7500+TL-NVDU7606S*4」这种，价格只算一个还是全算？**
A：**全算**。参数填 TL-VS7500 的，价格 = 解码矩阵 + 板卡×4 的总价。详见第三节「组合型号怎么算」。

**Q：为什么脚本算的价跟我填的不一样？**
A：脚本**不会改你填过的值**。不一致通常是你当时有特殊商业决策（加了利润点、A/B 成对按 2 个卖、按张/米计价、谈判议价）。
脚本会在报告里把这些行列出来，你确认即可。
