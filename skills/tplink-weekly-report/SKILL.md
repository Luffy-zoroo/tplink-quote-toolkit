# TP-LINK 配单清单周报

## 用途

把一周陆续收到的配单/询价清单，转成一份可直接修改的周报草稿：每个项目一段（**项目背景 → 配单内容 → TP-LINK 设备估价**），文末是"其他事项"。

**不写汇总表**（用户明确不要）。**不做整目录扫描**。

## 目录约定

| 路径 | 用途 |
|---|---|
| `<周报目录>\` | 周报工作根目录 |
| `…\周报\本周清单\` | 当天清单的副本，由 `week_log.py add` 自动复制进来 |
| `…\周报\项目背景.md` | 登记表：按周分节，每行 = `登记日期 \| 清单文件 \| 项目背景（口头补充）` |
| `…\周报\周报草稿MMDD.md` | 周报草稿产物 |

登记表是按周分节的，**它是"本周有哪些清单"的唯一依据**——不靠文件时间戳猜。

## 三种用法

### 用法 A：每天登记清单（最高频）

用户发来清单 + 口头描述时，登记：

```bash
<PY> <SKILL_DIR>/scripts/week_log.py add \
  --file "D:\...\0909视频监视系统-某项目清单-.xlsx" \
  --file "D:\...\附件1：监控系统清单0908.xls" \
  --note "某集团监控项目，清单数量与图纸对不上；附件1 是甲方给的询价版本"
```

- 脚本会把文件**复制**进 `本周清单\`（原文件不动），并把一行写进登记表本周小节；同名重复登记只更新背景。
- `--note` 是用户的口头补充，**照原话记，不要改写、不要补充用户没说的内容**；用户没给描述就留 `（待补充）`。
- 用户一次给多个清单且属于同一项目时，一条 `--note` 写清是哪个清单对应哪个说法；分不清就让用户确认，别硬套。
- 登记完给个短回执：登记了哪几个文件、本周累计几个、背景记了什么。

> **⚠️ 致命边界：用户说"登记"就只登记，不要顺手做分析。**
> 用户平时会一次丢好几个清单过来，其中**很多是别人的参数、别人的单**，他只是要存档备周报用。此时除登记外**什么都不要做**——不要做可做性梳理、不要核参数型号、不要算价、不要生成额外 md 文件。
> 只在用户**明确要求**时才深入分析，触发词如："核一下""能不能做""报个价""这单有没有戏""帮我看看"。
> 判断不了就问一句"这个要我细看还是先登记？"，**不要默认开工**。

### 用法 B：周末生成周报

```bash
<PY> <SKILL_DIR>/scripts/week_log.py list            # 看本周登记了什么、背景是什么
<PY> <SKILL_DIR>/scripts/tp_estimate.py "<本周清单\xxx>" --md-out "<临时明细.md>"   # 逐行明细，必须核验
<PY> <SKILL_DIR>/scripts/draft_report.py --week --out "<周报目录>\周报草稿MMDD.md"
```

`draft_report.py --week` 会自动读取本周登记表里的清单与背景，生成骨架（背景已填、无汇总表）。
随后在骨架上补写"配单内容"，写成最终草稿；格式见 `references/report_format.md`。

**补写"配单内容"的做法**：对每个清单逐个跑 `tp_estimate.py ... --md-out "<临时.md>"` 拿逐行明细，读出主要型号/数量/子系统构成，再写成一句话。明细文件用完即删，别留在目录里。

**两个必踩的坑**：

1. **`tp_estimate.py` 只认 `TL-` 开头的型号，会漏掉域联（`YL*`）型号**。清单里若有 `YLR`/`YLS`/`YLAP` 等，脚本金额会**偏小**。
   实测：`普联_AP0917.xlsx` 脚本出 7,395 元（只有 TL-NFW6430 一行），全量实为 **17,405 元**，漏了 YLR6010-LE、YLS220PE-16G2F×3、YLAP530G易展版×30。
   → 遇到 YL 型号必须**手工补算**，条目里写明两种口径哪个是准的。
2. **`--md-out` 必须带文件路径**，只写 `--md-out` 会 `IndexError`。
3. **多 sheet 的"概算"类清单**（一系统一个 sheet）：脚本已能识别「概算成本综合价 / 概算成本总价」双层表头与「图纸核实工程量」数量列，并跳过合并单元格造成的重复行（2026-09-20 修，修复前出入口系统被 7 倍重复计数）。但**域联（`YL*`）/水星（`MSL*`）型号仍不在 TL- 口径内**。
   实测：`（普联概算）三联四联…清单` 脚本出 **291,503**（TL- 口径），含 YL/MSL 全量为 **331,502**，差 4 万。

**骨架的 TODO 与金额都要人工复核**：骨架金额可能是脚本口径（见坑 1），**以手工核过的为准**并在条目里说明差异。"配单内容"必须自己读明细写，不能留 TODO。

**两行型号相同 ≠ 重复行**：先看序号列。招标表里 TL-SG2210工业级 出现两次，实为序号 1.7.1 与 3.7.1 两个不同分项。

**⭐ 周报是给用户直接提交的，不是分析报告**（2026-09-20 用户原话："我是要直接提交的，你说的太详细了"）：

- 每条 2~4 行一段话，全文 80 行以内。配单内容只写**数量级 + 大类 + 2~3 个代表型号**，禁止逐个型号罗列。
- **核对过程、差异明细、脚本口径异常、合并单元格之类的技术细节一律不进草稿**；结论半句话带过，明细另存单独文件。
- 写完后自查一遍：凡是"用户看了要自己再删的句子"，直接不写。

### 用法 C：临时估价（不写周报）

用户只想问"这个清单里普联设备多少钱"：

```bash
<PY> <SKILL_DIR>/scripts/tp_estimate.py "清单.xlsx"            # 逐行明细
<PY> <SKILL_DIR>/scripts/tp_estimate.py --quiet "清单.xlsx"    # 只要合计
```

只报数字和口径，不登记、不生成周报。

## 硬性规则

1. **只读原件**：绝不修改用户的原始清单文件。只有 `week_log.py add` 会往 `本周清单\` 复制副本，这是允许的。
2. **背景来源只有两个**：清单文件名 / 清单内容能看出来的，以及用户的口头补充。
   - 用户说了 → 照原话（可精简语病，不改含义）。
   - 没说过、也看不出来 → 写"**项目背景未知**"。
   - 从文件名能看出的（如"某新建大楼弱电项目""某科技馆智能化清单（询价）"）→ 写成"从清单看为……（待确认）"。
   - 禁止编客户名、金额、招投标阶段、竞争对手。
3. **不编金额**：金额只能来自 数量 × 单价 或清单已填总价；算不出来的不填，并在同一条目里说明原因（缺数量 / 缺单价 / 数量为 0）。
4. **一律不写汇总表**，也不要写"金额合计"这类总账；每条项目各自给估价即可。
5. **跳过备份与临时文件**：`.bak`、`~$*.xlsx`（脚本已自动跳过）。
6. **清单内容不进长期记忆**：清单属投标敏感数据，只在工作目录产出文件。

## 清单格式不一怎么办

这类清单来自不同设计院/集成商，格式差异很大，**必须先跑 `peek_lists.py` 看结构再估价**：

```bash
<PY> <SKILL_DIR>/scripts/peek_lists.py "清单1.xlsx" "清单2.xls"
```

- 脚本已能处理：合并单元格表头、跨行表头、表头出现在表格中间的分区式清单、型号列在最右侧、列名带单位后缀、标题行伪装成表头、`.xls` 旧格式。
- 仍然会遇到的：多工作表需逐个看、数量列名直接写成项目名、同一型号在马甲列/合并行里重复。
- **估价结果必须逐行核验**（脚本默认输出逐行明细），重点看：数量没取到却出现巨大乘积、同型号重复出现（主备/多批次/多标段）、明显异常单价。
- 某个文件算出来是 0 或明显偏小/偏大时，用 `--md-out` 出明细，再直接打印那几行的原始单元格（`load_sheets` 后看 `grid`）来定位列错位，别硬猜。
- **区分"算不出"和"没价"**：先看该行有没有数字（打印原始单元格），再判断是列错位（脚本 bug，要修脚本）还是清单本身没填价（正常，写"清单未填单价，无法估价"）。某酒店项目 0915 那张就是两层表头 + 含税单价占位 0，属于前者，已修。
- 算不准就在条目里写明口径存疑（"可能重复计数""缺数量按 1 计，偏低"），不要给一个看起来很确定的错数。

## 运行环境

- Python：`~/.workbuddy\binaries\python\envs\default\Scripts\python.exe`（已装 openpyxl、xlrd）。
- 环境缺失时重建：`…\python\versions\3.13.12\python.exe -m venv …\envs\default`，再 `pip install openpyxl xlrd`。
- 路径含中文/空格/括号时一律用双引号包住；中文输出加 `PYTHONIOENCODING=utf-8`。
- 脚本支持 `.xlsx`（openpyxl）与 `.xls`（xlrd 2.x 仅支持 .xls）。
