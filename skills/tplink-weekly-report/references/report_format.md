# 周报格式与写作规则

## 一、文件形态

- 输出一个 Markdown 文件：`周报草稿MMDD.md`（MMDD 为交付日期，如 `周报草稿0906.md`、`周报草稿0913.md`），存在周报根目录 `<周报目录>\`，最后用 present_files 展示。
- 用户会在这个草稿上直接改，所以：**别写成报告体**，用便于删改的短段落；不要加太多小标题层级。
- **不要汇总表**、不要金额总账。

## 二、结构

```
# 周报（草稿 MMDD）

> 估价说明：<口径一段话>

## 本周配单项目

1. **项目名称（清单文件名）**：项目背景 → 配单内容与规模 → TP-LINK 部分估价 → 未计入部分及原因。
2. ...

## 其他事项（待补充）

- （配置类事项、跟进中项目等请自行补充/删除）
```

## 三、项目背景怎么写

背景只有两个来源，**按优先级**：

1. **用户的口头补充**（登记在 `项目背景.md` 里）——照原话写，可以顺语病、压缩长度，但不得增删事实。
2. **清单文件名 / 清单内容**——能看出来的（如"某新建大楼弱电项目""某科技馆智能化清单（询价）""某医院改造-商务标"）写成"从清单看为……（待确认）"。

两者都没有 → 写 **"项目背景未知"**，不要留空、更不要编。

禁止编造：客户名称、项目金额、招投标阶段、竞争对手、我方策略。

## 四、条目写法

句式：

```
**项目名称（清单文件名）**：项目背景。配单内容与规模（品牌、主要型号、数量级、子系统构成）。
TP-LINK 部分估价约 **X.X 万**（精确元数）；未计入的部分及原因。
```

- **项目名称**：有真实项目名就用它；没有就退化为清单文件名标识（如"监控系统-设备清单（0908）"）。
- **配单内容**：写清品牌与主要型号、数量级、子系统（如"224 台摄像机 + 7 台 32 路 NVR + POE/汇聚交换机 + 六类网线"）。
- **估价**：`约 X.X 万（156,152 元）`，先写万元便于阅读，括号里给精确值。
- **未计入部分必须点明**：例如"硬盘为希捷等非 TP 品牌未计""4 行数量为 0 未计入""该版报价无单价""多数行缺工程量，按 1 台估，偏保守"。

### 长度红线（2026-09-20 用户明确要求"太详细了，我是要直接提交的"）

**每个条目 2~4 行，一段话写完，全文控制在 80 行以内。**

- 配单内容**只写数量级 + 大类 + 2~3 个代表型号**，不要逐个型号罗列。写"摄像机 800+ 台、NVR 5 种规格、TUMS 平台"是对的；把 30 个型号名全铺开是错的。
- **核对/分析过程不进周报**。给出结论一句带过即可（如"已核全表价格：总部折扣口径，7 处单价偏高需修正，另需补 2 路停车授权"），逐项差异表放单独文件，不塞进草稿。
- **脚本口径异常、单元格合并、字段识别这类技术细节一律不写**。用户是拿它交上去的，不是给自己看排查记录的。
- 报价注意事项（口径、取整、授权漏项）只在**该条目确实需要用户决策**时用半句带过。
- 用户说"太详细"时，默认动作是重写草稿，不是加小标题分层。

## 五、估价口径（必须在文件开头声明）

- 只统计型号以 `TL-` 开头的行；
- 行金额 = 已填总价列，或 数量 × 单价；
- 数量缺失按 1 台/个计并标注；
- 数量为 0 的行不计；
- 不含施工辅材、其他品牌设备、施工费。

## 六、数据坑清单（核验时逐条对照）

| 坑 | 表现 | 处理 |
|---|---|---|
| 整目录扫描 | 命令无输出后被 SIGTERM | 只用登记表里的文件；同类目录里可能有上百个历史清单 |
| 合并单元格表头 | 表头读成 None，列定位失败 | 脚本已做合并值传播 |
| 跨行表头 | "金额(元)" + 下一行"综合单价/合价" | 脚本向上 3 行找数量列；两行表头都能识别 |
| 分区式清单 | 同一张表里"有线网络/无线网络"两个分区，第二个分区中间又出现表头；表头之上的数据行易漏 | 脚本全表扫描，按型号列是否以 TL- 开头判定 |
| 型号列在最右侧 | 列序 … 数量 单价 小计 … 规格、型号 | 数量兜底必须排除价格列，否则会拿单价当数量（曾算出 1.2 亿的错误值） |
| 中文表头变体 | "数量（项目需求值）""工程量""综合单价 (RMB)" | 列匹配用"包含/前缀"而非"等于" |
| 标题行伪装成表头 | 标题含"报价明细表"被当成表头行；标题"某新区工程量清单"被当成数量列 | 表头行要选真正带单价/总价列名的那行；数量列名要求以"数量/工程量"开头，长标题句排除 |
| 列名带单位后缀 | "总价（元）""单价（元）""数量（项目需求值）" | 总价/数量列按前缀匹配，否则整列失效 |
| 数量列名是项目名 | 工程量清单里数量列的列头写成项目名（如"某新区"），无法识别 | 退化为逐行取已填总价、否则按单价×1，并在结果里标注"缺数量按1计" |
| 单价与总价口径不一致 | 单价列是不含电源的价格，总价列含电源（如 425 vs 474.5） | 优先取已填总价；剩余行按单价计，交付时说明口径 |
| 集采询价函 | 每行数量都是 1 | 结果是单价合计，必须注明"按量放大" |
| 主用/备用成对 | 同一套设备出现两遍（塔台主/备、两个标段、两个批次） | 给出合计并注明"若按一套约 X 万"，让用户判断 |
| 异常单价 | 如摄像机单价填成 4 元 | 在交付说明里点名，不要默默计入 |
| 同一文件多版本 | `xxx.xlsx` 与 `xxx.xlsx.bak`、两个近似文件名 | 跳过 `.bak`；近似文件提醒用户确认是否重复（登记表里用一行 note 记清版本关系） |
| 只有数量没有单价 | 视频监控/巡更/周界等子系统只填了数量 | 不计入估价，在条目里写明"该部分未计" |
| 网线等按米计价 | 六类网线 13,834 米 × 2.36 元，占比不小 | 算进去但单独点明口径，让用户判断是否保留 |
| 两层表头 + 占位 0 价 | 第一层表头"含税单价（元）"整列填 0，真价格在第二层表头的"单价/小计"列（某酒店项目 0915 清单） | 脚本已修：价格取到 0 视为未取到，自动回退到"真正有数据的数值列"重算；核验时确认金额取自哪一列 |
| 整表只有工程量、没有价 | 单价/金额列全空，表尾合计为 0 | **不是解析错误**，是空白计价表（甲方只给量）或只填了我方那一部分；条目写"清单未填单价，无法估价"，不要硬凑 |
| 比价/维保单表（整表没有数量列） | 某维保项目 0916：列只有 序号/名称/厂家/型号/参数/**价格**/单位，33 项只有 9 项填价 | **该表产出的"合计"实际是单价之和，绝不能当项目金额报**。条目里按"单价 × 单位"逐项列，写明"无数量列，只报单价、不出总价"；脚本会打印"缺数量按 1 计"，出现这句就要回头确认是不是这种表 |
| 只有部分行有价 | 某酒店项目清单 146 行里只有 20 行（TP-LINK 部分）填了价，其余开关插座/桥架/配线架无型号无价 | 说明这是"我方只报了 TP 部分"的半成品清单，条目里点明未计部分 |
| 招标对照型清单 | 某古建项目 0914：列结构为「参数」= 我方响应值、「属性」= 招标要求原文，末尾「备注」常写着偏离点（如"接口不满足""不带支架""私有平台"） | 估价照常；**额外把「属性 vs 参数」逐条比一遍**，能在报周报时直接点出负偏离位置（用户最关心"这单有没有戏"）；只陈述清单里写明的差异，不做技术判断给结论 |
| 招投标类清单 | 表头带"项目编号 JXSY-ZFCG-[2026]第 12 号-3""是否属于品目清单内的节能产品/环境标志产品/本国产品"等合规列 | 记录项目编号与招标属性；这类清单的量价通常只填了部分品目，未填的按"待报"说明 |

## 七、历史样例（复刻语气可直接读）

- `<工作区>\周报草稿0906.md`：13 个清单（医院商务标、汇总表、航管工程询价、科技馆询价等）。
- `<工作区>\周报草稿0913.md`：7 个清单（视频监视、监控清单、集采询价函、产教融合实训基地、工程清单、机场项目等）。

注意：这两个样例里有"## 汇总"表，那是早期版本；**现行版本不要汇总表**。
